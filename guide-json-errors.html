JSON 为什么校验失败？10 个高频格式错误

最后更新：2026 年 8 月

JSON 报错时，问题通常不是数据“坏了”，而是一处很小的语法不符合严格 JSON 规则。下面按最常见的顺序排查。

1. 键名没有使用双引号

严格 JSON 的对象键名应该写成双引号字符串。不要把 JavaScript 风格的裸键名直接当成 JSON。

2. 字符串用了单引号

JSON 字符串使用双引号。看到大量单引号时，先检查数据是否其实是某种编程语言对象，而不是严格 JSON。

3. 最后一项后面多了逗号

JSON 不允许在对象或数组最后一个元素后保留尾逗号。删除最后一项后面的逗号通常即可解决。

4. 少了逗号

相邻的两个键值对或数组元素之间需要逗号分隔。检查报错位置附近的上一项，往往比只盯着当前字符更有效。

5. 大括号和方括号没有配对

对象必须成对使用 {}，数组必须成对使用 []。嵌套很多层时，可以先格式化已有片段，让缩进帮助你寻找缺失的括号。

6. 把 true、false、null 写成字符串

如果数据需要布尔值或空值，应该使用 true、false、null，而不是把它们写成带引号的文本。两者的数据类型不同。

7. 字符串中的双引号没有转义

如果字符串本身包含双引号，需要按 JSON 的转义规则表示。否则解析器会把内部双引号误认为字符串结束。

8. 把注释直接写进 JSON

严格 JSON 本身没有 JavaScript 那样的 // 或 /* */ 注释语法。如果配置系统支持注释，那通常是它自己的扩展，不代表文本仍是标准 JSON。

9. 数字格式不符合 JSON

数字不能随意加入单位、逗号或其他文本。需要表达“100 元”时，应根据数据设计决定是数字 100 还是字符串“100 元”。

10. 复制时混入不可见字符

从网页、文档或聊天软件复制内容时，可能混入特殊空白或全角标点。遇到难以解释的错误，可以把内容分段粘贴到校验工具中定位问题。

推荐的排查顺序

  1. 先确认最外层是完整对象或数组。
  2. 检查所有键名和字符串是否使用双引号。
  3. 检查逗号、括号和引号是否成对。
  4. 检查 true、false、null 的类型。
  5. 最后再检查字符串内部的转义和复制产生的特殊字符。

你可以使用JSON 格式化与校验工具快速验证结果。工具在浏览器中处理输入，不需要把内容发送到服务器。

结语

JSON 调试最有效的方法通常不是反复修改整份文件，而是从语法结构最基础的部分逐层排查。找到第一处解析失败的位置后，后面的连锁报错往往会一起消失。
